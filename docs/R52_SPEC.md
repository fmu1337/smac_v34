# SMAC Ultr@ R52 — точная спецификация (по декомпилятору)

Этот документ сделан по `tools/r52re/decomp.py`. Это декомпилятор байткода SourcePawn в псевдокод: он сворачивает
XOR-пары и opaque-предикаты SmartPawn по памяти после `OnPluginStart` и собирает `&&`/`||` на стыках блоков.
Условия ниже взяты из кода напрямую, а не из поиска путей. Там, где они расходятся с `R52_DECODED.md`, верен этот документ.

Обозначения: `cnt[i]` — per-client массив счётчиков `g3d674[client][i]`; `sens` — значение `sensitivity` клиента
(запрашивается `QueryClientConVar`); `s = RoundToNearest(sens)`; `dYaw` — `|yaw(cmd) − yaw(prev cmd)|` без нормализации
через 360 (берётся из кольцевой истории углов на 45 записей, `g2601c`); `mouse` — `mouse[0..1]` из `OnPlayerRunCmd`.

## 0. Общий каркас

### 0.1 Пороги от sensitivity клиента (`QueryClientConVar("sensitivity")`)

| Порог | Формула | Где используется |
|---|---|---|
| `thr2` | `sens · 0.033` | PRG 301/302, Accurate Analysis, UsingWH 102 |
| `thr3` | `min(thr2 · 2.6, 0.7)` | Accurate Analysis (вход), отметка «снапа» для AGTWS |
| `thr4` | `min(sens · 15, 80)` | — |
| `thr5` | `max(sens / 8.5, 0.2)` | UsingWH 103 |
| `s` | `RoundToNearest(sens)` | AMSAF, PRG 303/304 |

* Пока клиент не ответил: `thr2 = thr3 = 100`, `thr4 = thr5 = 10000` (это и есть «100°» из старого декода).
* `sens < 1` → кик `SMAC_Sensitivity_L`; `sens > 20` → кик `SMAC_Sensitivity_H`.
* Смена `sensitivity` больше `|smac_antispam_Mouse_Sensitivity|` раз за карту → кик (−) или бан (+).

### 0.2 Наказание и сетевой гейт

`Punish(client, action, …)` (`fn_1481bc`): 1 = уведомление админам, 2 = кик, 3 = бан. Перед киком или баном
(`fn_37f6a4`) действие понижается на ступень, если средний пинг клиента ≥ 0.15 с, и ещё на ступень, если входящих
пакетов ≤ 46.2/с. В причину дописываются `[L…]` / `[A…]`.

### 0.3 Затухание счётчиков

Каждый детект вызывает `SetBan(client, code, delay)` (Ultr@Tools: отложенный колбэк `OnBanReleased`). По срабатыванию
`cnt[idx]--`, если игрок за T/CT; если он зритель, проверка откладывается снова. Обычная задержка 420 с, у части детектов 300 с.

| code | cnt | детект | code | cnt | детект |
|---|---|---|---|---|---|
| 12 | 3 | AGT 288/299 | 305 | 14 | Advanced Trigger |
| 14 | 9 | AGTAF 88/99 | 307 | 16 | AGTWS 100 |
| 16 | 1 | Trigger 188/199 | 308 | 17 | AGTNL 200/201 (300 с) |
| 101 | 12 | AMSAF 101 (480/540/600 с) | 400 | 19 | KnifeBot (1024 с) |
| 102 | 20 | UsingWH 102 | 401–404 | 21–24 | Eyetest 01–04 (528 с) |
| 103 | 18 | UsingWH 103 | 407 | 29 | Backtrack |
| 301/302 | 4/5 | PRG 301/302 | 412/413 | 35/37 | Act.Mode (PRG) |
| 303/304 | 7/8 | PRG 303/304 (300 с) | 414 | 38 | AGTAF 108/109 |
| 1101/1102 | 42 | No Recoil A/B (финальная проверка) | 416 | 43 | PSilent |

При смерти жертвы (`player_death`) её счётчики `cnt[1]`, `cnt[3]`, `cnt[9]`, `cnt[12]` уменьшаются на 1, а если они > 1,
ставится отложенная проверка.

### 0.4 Трасса «на цель» (`fn_35cd2c(client, angles, mode)`)

* Луч из глаз по углам cmd. Для режима 0 к yaw добавляется зонд `probe`, а глаза опускаются на `probe·180`: если прошлая
  трасса никого не нашла, `probe += 0.01`, сброс в 0.005 после 0.1. Это «Act.Mode probe» из старого декода.
* Попадание засчитывается, если цель — игрок другой команды и дистанция² ≥ 40000 (200 юнитов).
* Режим 1 (PRG 301/302) и режим 2 (PRG 303/304, AGTAF) ведут **стабильность хитгруппы**: запоминаются первые две
  разные хитгруппы, счётчик `hits` растёт, пока луч попадает в одну из них, а на третью хитгруппу сбрасывается в −1.
  Окно: 5 трасс (режим 1) или 11 трасс (режим 2). Aimbot всегда бьёт в одну кость, человек — нет.

## 1. Aim в `OnPlayerRunCmd`

Общий вход: игрок валиден (`state > 1`) и не помечен.

### 1.1 Мышь стоит (`mouse[0] == 0 && mouse[1] == 0`), игрок на земле

**PRG Pass.Mode:301/302** (`smac_aimbot_Advanced_*_PRG`):
1. `dYaw > thr2` → `cnt[2]++`. Иначе ветка AGTNL 200 ниже, а `cnt[2] = −1`.
2. При `cnt[2] > 0`: оружие из trie исключений → сброс. Иначе трасса режима 1:
   * цель есть и `hits ≥ 4` → **301**: `cnt[4]++`, `cnt[2] = −1`;
   * при `cnt[2] > 5`: `cnt[4] ≥ 0` и `hits ≥ 2` → **302**: `cnt[5]++`; при `cnt[2] > 10` → сброс.
3. Бан или кик при `cnt[4|5] > |Ban_PRG|`, уведомление при `cnt ≥ Warning_PRG`.

Иначе говоря, PRG ловит взгляд, повёрнутый **на 1.5 «тика мыши» и больше без ввода мыши**, когда луч стабильно попадает
в одну хитгруппу противника. Порог 100° из старого декода — значение до ответа клиента о sensitivity.

**AGTNL Mode:200** (`smac_aimbot_Advanced_*_AGTNL`): `0.005 < dYaw < 0.007`, нет зума (`m_iFOV > 50`), прошло больше
22 cmd с прошлой проверки, трасса режима 0 на противнике → `cnt[17]++`, кулдаун 22 cmd.

### 1.2 Мышь двигается

* В `g54ca8[client][0..1]` сохраняется `|mouse|`.
* **AGTNL Mode:201**: прошло больше 22 cmd с прошлой проверки, `|Δpitch| < 0.005` и `|Δyaw| < 0.005` (мышь двигается,
  а углы стоят), так 5 раз → `cnt[17]++` (если в руках есть оружие).
* **PRG Pass.Mode:303/304** (на земле): мышь движется ровно, без рывков:
  `!(|mouse0 − prev0| > s && |mouse1 − prev1| > s)` → `cnt[6]++`. Иначе `cnt[6] = −1`. При `cnt[6] > 0`, если трасса
  режима 2 на цели:
  * `hits ≥ 10` → **303** (`cnt[7]`);
  * при `cnt[6] > 11`: `cnt[7] ≥ 0` и `hits ≥ 8` → **304** (`cnt[8]`); при `cnt[6] > 22` → сброс.
* **Act.Mode** (`fn_36228c`, коды 412/413) запускается при `+attack` без `+duck` и после кулдауна. Нужно, чтобы
  `0.005 < probe` и `2 ≤ hits ≤ 5`. Сравнивается `m_angEyeAngles` с углом cmd, сдвинутым на зонд; два раза подряд → детект
  с режимом из строки `"300.x"`.

### 1.3 AMSAF Mode:101 (`smac_aimbot_Advanced_*_AMSAF`) — квантование мыши при стрельбе

Шкала: `bucket(m) = 0` при `m == 0`, иначе наименьшее `k`, при котором `m ≤ k·s` (не больше 8).

1. **Взвод на первом выстреле** (фронт `+attack`): игрок остановился за ≤ 1 cmd до выстрела (`vel == 0`), окно 6 cmd,
   `m_angEyeAngles` изменился. Условие взвода по |mouse| в момент выстрела:
   * `bucket == 8` (рывок больше 7·s) — по любой оси;
   * `bucket ≥ 3`, обе оси ≥ s, хотя бы одна ≥ 2s;
   * `bucket == 2`, обе оси ≥ 2s, хотя бы одна ≥ 3s.
2. **Второй cmd удержания** (`cnt[10] == 2`): та же шкала и накопленная сумма |mouse| ≥ 9·s. Каждое совпадение даёт
   `score++`, плюс `score++`, если трасса режима 0 на цели.
3. **Третий cmd** (`cnt[10] == 3`): шкала до 3. «Доводка» — обе оси в диапазоне `[2s; 5s]`, `[s; 3s]` или `≤ 2s`
   соответственно, тоже `score++` и `+1` за цель.
4. **На отпускании `+attack`**: если `score > 1` (и, при удержании дольше 3 cmd, угол действительно менялся) → `cnt[12] += score`.
   Уведомление или наказание по `*_AMSAF`; при `score` 1/2/≥3 ставятся задержки 480/540/600 с.

### 1.4 AGTWS Mode:100 (`smac_aimbot_Advanced_*_AGTWS`) — «докрутка» после снапа

* Во время `+attack` запоминается cmd, где `dYaw ≥ thr3` («снап»).
* Затем, не позже 7 cmd после снапа, ловится cmd с `dYaw == 0` ровно, но с изменённым pitch (то есть yaw замер, а pitch
  довёлся). Если трасса режима 0 на противнике → `cnt[16]++` (код 307).

### 1.5 Advanced Trigger

См. §6b.

## 2. Accurate Analysis Module (`player_hurt` / `player_death`)

* `player_hurt`: здоровье жертвы > 0, `dmg_health ≥ 10`.
* `player_death`: хэдшот берётся из события.
* Не в себя, оружие не из trie 4104 (гранаты и т. п.). `AAM(attacker, victim, headshot, dist², weapon, mode, dmg)`.
* Анализ только при `dist² ≥ 40000` (200 юнитов).

**Вход в AGT и Trigger:** `(dYaw ≥ thr3 && cnt[2] > −1) || (dYaw > thr2 && cnt[2] > 0)`. То есть в момент попадания
прицел ещё поворачивался без мыши (PRG-стрик активен).

**Вес `w`** (только для `player_death`):

| `dYaw` | `cnt[2] > 1` | иначе |
|---|---|---|
| > 2 | 3 | 2 |
| > 0.6 | 2 | 1 |
| > 0.4 | 1 | 1 |
| иначе | 0 | 0 |

**Прибавка** (одинаковая для AGT `cnt[3]` и Trigger `cnt[1]`), `T5 = trie 4105`, `T6 = trie 4106` — группы оружия:

| дистанция | хэдшот | без хэдшота |
|---|---|---|
| < 550 | T5: `w+1`; T6: `w+3`; иначе `w+2` | T6: `w+2`; иначе `w+1` |
| 550–1300 | T5: `w+3`; иначе `w+2` | T5: `w+2`; иначе `w+1` |
| > 1300 | T6: `w+2`; T5: `w+3`; иначе `w+2` | T5: `w+2`; иначе `w+1` |

* **AGT Mode:288/299:** `cnt[3]` > `|Ban_AGT|` → бан (+) или кик (−), затем `cnt[3] = −2`. Уведомление с режимом
  299 (hurt) или 288 (death).
* **Trigger Mode:188/199:** то же на `cnt[1]`, но только если `cnt[0] > −1`, то есть попадание в течение 2 cmd после
  фронта `+attack`.
* **AGTAF Mode:88/99 и 108/109** (счётчики `cnt[9]` и `cnt[38]`) — по стрику PRG 303/304 `cnt[6]` и стабильности хитгрупп
  трассы режима 2:
  * `2 < cnt[6] < 5`, `hits > 2` и все трассы в одну хитгруппу → `cnt[9] += 1 (+1 за хэдшот)` (99 hurt / 88 death);
  * `cnt[6] ≥ 5` и (`hits > 2 && ≥ 5 стабильных` или `hits ≥ 4 && ≥ 4 стабильных`) → `cnt[38] += 1 (+1)` (109/108).

## 3. Прочее, найденное в `OnPlayerRunCmd`

* **No Recoil B** (`fn_1853f4`): `|Δpitch| ≥ 1.1` и больше 1.5× максимума серии → `SetBan(1102, 1..3 с)`, затем
  финальная проверка `cnt[42] > |smac_NoR_Ban|`.
* **No Recoil A:** во время `+attack` берётся cmd pitch/yaw против `m_angEyeAngles`. Счётчик рассинхрона > 50 →
  `SetBan(1101, 1..3 с)`.
* **Eyetest 01/02/03** (`smac_eyetest_reaction`, «E.T.Violation→CmdNum»):
  * 01: cmdnum меньше предыдущего;
  * 02: cmdnum повторился, а tickcount не равен прошлому и не прошлому+1;
  * 03: cmdnum повторился, а кнопки из маски `0x10618` изменились.
* **Eyetest 04:** pitch вне ±89.9 или roll вне ±30.
* **AutoTrigger** (`smac_autotrigger_ban`): кнопка переключается каждый cmd N раз подряд. Атака — 5 (Auto-Fire),
  `+moveleft`/`+moveright` — 5 (Auto-Strafe), `+duck` — 5, `+jump` — 25 (Auto-Scroll). Тип 0 (BunnyHop) ведёт
  таймер на 22 cmd от нажатия `+jump` на земле; точный смысл таймера не проверен.
* **Advanced BunnyHop** (`fn_344b08`): EMA тиков на земле перед прыжком `g = (9g + n)/10`. При `g < 1.1` и скорости
  ≥ 350 растёт счётчик, 12 → детект. При `g > 15` проверяется авто-скролл, при `g ≥ 0.8` — HaX2.
* **CheatCFG** (`smac_css_CheatCFG`, 1..3; > 3 — лига):
  * Stop movement: прошлые кнопки ровно одна из `{8,16,512,1024,520,1032,528,1040}`, текущие ровно `IN_ATTACK`, > 7 раз;
  * Fast switch: смена `m_hActiveWeapon` за ≤ 2 cmd после атаки, > 7 раз;
  * Fast Reload: `m_flNextPrimaryAttack`, `m_flNextAttack`, `m_flNextSecondaryAttack` изменились при том же оружии.
* **SIC «Fast Run»** (`smac_FD_BHOP`, внутри SIC): wishmove против кнопок и `|vel.x|` или `|vel.y|` > 289, > 22 раз.
* **SIC «до входа в игру»:** клиент шлёт ненулевой `mouse`, пока его состояние < 1 (не вошёл), → кик или бан.
* **Lag Exploit** (`fn_1464c`): четыре последних cmd обработаны в серверные тики, идущие строго подряд (разница 1), а
  между двумя последними `|cmdnum|` **или** `|tickcount|` вырос больше чем на 11. Счётчик за карту не затухает,
  > 5 → всегда бан `SMAC_Hack (Lag Exploit)`. Порт в `smac_ultra_netcode` строже: требует cmdnum +1..11 и сбрасывает
  серию через 5 с, иначе потеря > 11 пакетов подряд (cmdnum скачет) давала бы бан.

## 5. Посекундный тикер (`OnTimerUp`)

`OnTimerUp` вызывается раз в секунду (Ultr@Tools). Для каждого игрока:

| Детект | Условие | Квар |
|---|---|---|
| **Spinhack** | `Σ|Δyaw|` за секунду (с нормализацией через 180/360) > `420·sens` **или** > 4096; больше 5 таких секунд → кик | — |
| **Teleport Hack** | смещение за секунду² > `SpeedTeleport²` при обычном movetype → бан (+) или кик (−) с дистанцией | `smac_SpeedTeleport` |
| **Teleport: Fast Detect** | `|vel.z| > 1250` → SIC с тем же знаком | `smac_SpeedTeleport` |
| **BunnyHop: Fast Detect** | в секундном срезе `|vel.x|` или `|vel.y|` > 289 при обычном movetype → сразу SIC-реакция | `smac_FD_BHOP` |
| **Airstuck: Fast Detect** | скорость не меняется (каждая компонента < 0.7) при флагах ровно `0x10280`/`0x10282` (в воздухе), 3 секунды → реакция | `smac_Airstuck_reaction` |
| **RCS -H** (`Eye_Angle_Test_Hurt`) | сумма `|Δpitch|+|Δyaw|` на тиках, где было попадание, за секунду > `|Hurt|` (по умолчанию 4); больше 2 секунд → SIC | `smac_Advanced_Eye_Angle_Test_Hurt` |
| **RCS -F** (`Eye_Angle_Test_Fire`) | та же сумма на тиках стрельбы без попадания за секунду > `|Fire|` (40); больше 8 секунд → SIC | `smac_Advanced_Eye_Angle_Test_Fire` |
| **AutoHotKeys** | `+left` и `+right` больше 6 раз каждая за секунду → AutoTrigger тип 6 | `smac_autotrigger_ban` |
| **SpeedLimit** (`SpeedUp`/`SpeedLimitDetect`) | cmd в секунду > `ceil(66·SpeedUp)` (80): счётчик +1 (≥ 132 cmd — ещё +3); при превышении `|SpeedLimitDetect|` проверяются avg packets in/out > 46.2 и avg data > 66·30·2.2 → «FakeSendPacket[Max]» | `smac_SpeedUp`, `smac_SpeedLimitDetect` |
| **Fake Lag** | cmd в секунду < `round(66·0.2)` = 13 → «FakeSendPacket[Min]»; данные in/out с соотношением ≤ 2.9 и пакетами ≤ 25 не наказываются | `smac_FL_Ctrl` |
| **DDoS** | avg data клиента выше порога при пакетах > 46.2: +3, больше 3 → «DDoS Exploit» | `smac_DDoS_Ctrl` |

Ещё он раз в 5 секунд сбрасывает `sv_cheats` в 0, отключает модули при `host_timescale != 1` и раз в цикл
перезапрашивает `sensitivity` и `cl_mouseenable`.

## 6. Уточнения по `OnPlayerRunCmd`

* **Airstuck** (`smac_Airstuck_reaction`): cmdnum = прошлый + 1, а tickcount повторился, и игрок не «стоит»
  (кнопки, мышь или углы ненулевые/изменились) → `cnt[25]++`. 6 → `cnt[26]++`, `cnt[25]` сброс; `cnt[26] ≥ 2` → реакция.
  Повтор tickcount не подряд сбрасывает `cnt[25]`. Совпадает с портом `smac_ultra_netcode`.
* **Fast AIM Detect** (`smac_Fast_AIM_Detect_*`): выстрел, где за первые 6 cmd менялись и pitch, и yaw, и **был нанесён
  урон** (AAM добавляет `dmg` в окно). Затем на отпускании атаки углы ровно равны прошлым → `cnt[30]++`.
* **2X** (`smac_method_2X_*`): машина состояний `g4d81c[client][3]` на фронтах атаки (двойной клик за выстрел),
  детект в состояниях 103–104. Точный автомат не расписан.

## 6a. Хук выстрела (temp-entity FireBullets, `m_iPlayer`)

Вызывается на каждый выстрел стреляющего игрока. `cmdHist[k] = {cmdnum, tickcount, server_tick}`, `[3]` — последний cmd.

* **PSilent [Active Mode]** (`smac_PSilent_*`). Выстрел «взводит» стрелка, если:
  * у последних 4 cmd cmdnum и tickcount растут ровно на 1;
  * server_tick `[1]−[0] == 1`, `[2]−[1] ∈ {0,1}`, а `[3]−[2] > 1`: последний cmd пришёл после разрыва, то есть выстрел зачокан;
  * в момент выстрела есть заметное движение: `dYaw > 1.5·thr3` или изменение |mouse| > `1.5·thr4`.

  Дальше в `OnPlayerRunCmd` при удержании атаки: если server_tick двух последних cmd совпадает, а `[0] != [1]`,
  счётчик растёт, > 2 → `cnt[43]++` → реакция по `smac_PSilent_Ban` (код 416).
* **No Recoil.** На выстреле запоминаются углы, затем в `OnPlayerRunCmd`:
  * A (1101): cmd-углы совпадают с `m_angEyeAngles` (pitch и yaw) больше 50 cmd подряд при стрельбе;
  * B (1102): после выстрела pitch меняется, а `m_angEyeAngles[0]` нет; на отпускании атаки `|Δpitch| ≥ 1.1` и больше
    1.5× максимума серии.

  Итог — `cnt[42] > |smac_NoR_Ban|` в `OnBanReleased` (через 1–3 с).
* **Backtrack Exploit-Mode:A** (`smac_eyetest_reaction_Advanced`): на выстреле tickcount меньше прошлого (или < 0),
  больше 2 раз → реакция. **Mode:B** (в `OnPlayerRunCmd`): cmdnum меньше прошлого, больше 22 раз.
* **CheatCFG Fast Reload:** на выстреле запоминаются `m_hActiveWeapon` и `m_iClip1`.
* **UsingWH 102/103** (`smac_aimbot_UsingWH_*_AMS`). Несмотря на название, от anti-WH не зависят: это окно 6 тиков
  после первого выстрела в серверном тике.
  * **103:** за окно, на тиках без ввода мыши и на земле, накоплено изменение углов `Σ|Δ| (> thr2 на тик) ≥ thr5`, и был
    урон → `cnt[18]`.
  * **102:** в начале окна мышь дёрнулась на ≥ 8·s, затем 1–3 cmd без мыши с ровно равными углами, и был урон → `cnt[20]`.

## 6b. Прочее

* **Advanced Trigger** (`smac_AdvancedTrigger_*`, код 305): два нажатия `+attack` подряд, каждое длиной ровно 1 cmd
  (кнопка отпущена в следующем же cmd), → `cnt[14]`. Человек держит клик несколько тиков.
* **Advanced AutoFire** (`smac_AdvancedAutoFire_*`, код 306, в `OnTimerUp`): то же состояние «одно-тиковых» нажатий,

* **KnifeBot** (`smac_KnifeBot_UsingWH_*`, код 400): удар ножом `+attack2` открывает окно 6 cmd. Удар засчитывается, если
