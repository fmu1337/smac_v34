# SMAC Ultr@ R52 — что реально делают детекты (декод `001_SMAC_Global.smx`)

> **Обновление:** точная спецификация по декомпилятору — `docs/R52_SPEC.md`. При расхождении верна она.
> Главная поправка: порог PRG и Accurate Analysis — не 100°, а `sensitivity·0.033`; 100 — значение до ответа клиента.

Источник: архив R52 (2018-04-09, `0.8.6.4+[SMAC]<Ultr@>-R52`), плагин обфусцирован SmartPawn.
Метод: собственный эмулятор SourcePawn VM (`tools/r52re`) — расшифровка строк в `AskPluginLoad2`,
конкретный прогон `OnPluginStart/OnConfigsExecuted/OnMapStart/OnClientPutInServer` с квара­ми из штатного `smac.cfg`,
затем символьное исполнение `OnPlayerRunCmd`/`OnTimerUp`/`OnBanReleased` с направленным поиском пути к каждому детекту.

Уверенность: **высокая** — условия видны на нескольких независимых путях; **средняя** — один путь / часть переменных не опознана;
**низкая** — понятен только общий смысл.

> Важно: R52 — крякнутая сборка (`SMAC_Ultr@_key "GHETT90CR4CK0YE4HH"`) с IP/лицензионной обвязкой
> (`46.174.52.246:22222`, проверка размеров `Ultr@Tools.ext.*` = 79360/126896, `compile.so`, `hostip`). На проде не запускать.

## 0. Архитектура R52 (то, чего нет в #7)

* `OnPlayerRunCmd` в первую очередь **пишет историю** на клиента: кольцевые буферы `[cmdnum, tickcount, server_tick]`,
  углы, `mouse[]`, кнопки (текущие/прошлые). Детекты — отдельные блоки ниже, многие проверки — в `OnTimerUp`
  (тикер Ultr@Tools.ext) и в отложенных колбэках `OnBanReleased(client, code)`, которые ставятся через `SetBan(client, code, rnd)`.
* **Общий предфильтр aim-детектов** (высокая): `!(btn & IN_USE)`, `cmdnum == prev_cmdnum + 1` (нет потерянных/зачоканных cmd),
  `tickcount != prev_tickcount`; почти все aim-режимы — **только на земле** (`FL_ONGROUND`); оружие из trie-исключений пропускается.
* **Двухступенчатые счётчики**: streak-счётчик (сбрасывается при нарушении паттерна) → счётчик детектов → warn/ban квары.
* **Гейт наказания по сети** (высокая, видно в PSilent): действие только если `GetClientLatency(out) < 0.15` и
  `GetClientAvgPackets(in) > 46.2` (≈70% от 66 cmd/s). Админы с флагами ≥ `ADMFLAG_BAN` пропускаются.
* Пул констант SmartPawn (заполняется в `OnPluginStart`): `0.1, 1.5, 180, 360, 0.7, 89.9, 16, 3025(=55²), 2.9, 289(=17²), 0.2, 0.15, -30, 40000(=200²), 302500(=550²), 1.69e6(=1300²), 1250, 900`.
* R52 **доверяет `mouse[]`** в v34, но использует его иначе, чем #7: требует `mouse == 0` ровно, в сочетании с жёсткими
  признаками (скачок >100°, сдвиг 0.005–0.007°), либо анализирует **квантование** `mouse[]`.

## 1. Aim (соответствует `smac_ultra_aim`, `smac_aimsnap`, `smac_firemacro`, `smac_advtrigger`)

| Детект R52 | Условие (декод) | Уверенность |
|---|---|---|
| **PRG Pass.Mode 301/302** | предфильтр + `mouse0==0 && mouse1==0` + на земле + `|yaw_ref − ang1| > 100°` (yaw_ref — опорный угол игрока) → streak; 301: streak≥1 и трасса из глаз попадает в игрока, hitgroup-счётчик ≥4; 302: streak>5, трасса не попала; второй счётчик >1 | высокая |
| **PRG 303/304** | `mouse ≠ 0`, на земле, разница `mouse0` с предыдущим ≤ базового шага; 303: трасса в игрока, hit-счётчик ≥10; 304: streak>11, hit-счётчик ≥8 | средняя |
| **AGTNL Mode 200/201** | предфильтр, на земле, `|Δyaw| ≤ 100`, **`0.005 < |Δyaw| < 0.007`** (микрошаг), трасса в игрока, streak >1 | высокая |
| **AMSAF Mode 101** (`AimbotDetected_4`) | анализ **квантования мыши**: базовый шаг `unit` на клиента; сравнение `mouse0/1` с `2·unit, 3·unit, 5·unit, 7·unit, 9·unit`, суммы двух тиков; счёт «точных кратных» | средняя |
| **Act.Mode 300** | сверка `m_angEyeAngles[0]` с углом cmd + «зонд» с микро-смещением (+0.01, до 0.1) и ограничением `cmdnum > state+132` | низкая |
| **Fast AIM Detect** | атаку отпустили, `IN_ATTACK2` нет, прошлый тик стрелял, внутри окна `cmdnum ≤ shot_cmd+6`, которое открывается выстрелом с изменением pitch **и** yaw, и при этом углы **точно равны** предыдущим (`ang == prev`) | высокая |
| **Advanced Trigger** | фронт атаки (прошлый тик без `IN_ATTACK`), pitch не изменился, `|yaw_ref−ang1| < 100`, ряд флагов состояния, счётчик ≥1 → `AdvancedTrigger_1` | средняя |
| **UsingWH 103 / KnifeBot** | работают только с Anti-WH: значение ≥ 10000 (квадрат дистанции/времени) для 103; KnifeBot — атака в окне `cmdnum < window` после события, счётчик >1 | низкая |

Вывод для #7: `smac_ultra_aim` из #7 **не соответствует R52**. В #7 номера режимов (100, 101, 109) используются как пороги в
градусах, а «мышь стоит» — это `|mouse| ≤ 2` при сдвигах от 0.4°. В R52 это скачок >100° при `mouse == 0`, сдвиг ровно
0.005–0.007°, квантование мыши. Модуль нужно переписать по таблице выше или выключить.

## 2. PSilent [Active Mode] (соответствует `smac_psilent`)

Высокая уверенность по блоку, средняя по «взводу»:
`IN_ATTACK` в текущем **и** предыдущем cmd; взведённое состояние (`state > 0`, ставит обработчик выстрела);
последний элемент истории имеет `server_tick == текущий server_tick` (две команды обработаны в одном серверном кадре = пришли
одним пакетом, то есть **choke на выстреле**), а `server_tick[-2] != server_tick[-1]`; streak ≥ 3 → детект;
наказание только при пинге < 150 мс и avg packets > 46.2 (кик по умолчанию после 12: `smac_PSilent_Ban "-12"`).
В #7 стоит StAC-проверка A-B-A по углам. Это другой признак, у R52 его нет.

## 3. No Recoil A/B (соответствует `smac_norecoil`)

Оба режима сначала **планируют отложенную проверку** `SetBan(client, 1101|1102, GetRandomInt(1,3))`, а сам детект считается в
`OnBanReleased(client, code)` (счётчик >1, cfg `smac_NoR_Ban "5"`).
* Mode A (1101): стрельба с удержанием, счётчик рассинхрона `>50`; растёт, когда `cmd pitch == m_angEyeAngles[0]`, но
  `cmd yaw != m_angEyeAngles[1]` (cmd-угол против сетевого угла глаз). Уверенность средняя.
* Mode B (1102): `pitch == prev_pitch`, но `prev_pitch != m_angEyeAngles[0]`; затем `Δpitch ≥ 1.1` и `Δpitch > 1.5 × предыдущей Δ`.
  Уверенность средняя.
R52 **не читает `m_vecPunchAngle`**. Модель #7 («punch ≈ 0» и «зеркало punch») — другая.

## 5. CheatCFG / оружие

* **Stop movement, AIM CFG**: прошлые кнопки — ровно одна из комбинаций движения `{8,16,512,1024,520,1032,528,1040}`,
  текущие — **ровно `IN_ATTACK`** (стоп-стрельба биндом); streak > 7. Высокая. В #7 такого нет.
* **Fast Weapon Switch**: смена `m_hActiveWeapon` в пределах 2 cmd после фронта атаки; streak > 7. Высокая.
  В #7 считается «8 смен оружия за 0.5 с».
* **Fast Reload or Shooting**: при атаке и том же оружии сравниваются `m_flNextAttack`, `m_flNextPrimaryAttack`,
  `m_flNextSecondaryAttack` с прошлым тиком; счётчик ≥ 2. Средняя/низкая (полная формула не восстановлена).
  **Таблицы длительности перезарядки нет**, «55% от стока» в #7 — выдумка.
* **Using the button 2X**: огонь по `IN_ATTACK2` на оружии с кодом класса 103–104. Средняя.

## 6. «Защиты», которые в #7 стали детектами

* `smac_SoundESP` — режимы подмены координат и данных звука **только** при включённом Anti-WH и отсутствии прямой видимости.
  По умолчанию в R52 `0` (настоящие координаты). В #7 jitter включён по умолчанию, а `smac_soundesp` вырезает шаги.
* `smac_AIM_Kill` описан в cfg как «режим защиты», а не детект. В коде найдена рассылка поддельных координат игрока в
  radar-usermessage (Z + rand(500..1000)). В #7 это сделано детектом «килл после снапа».
* `smac_wallhack` в R52 хукает `Shotgun Shot` (TE). Глобального ±100u jitter для всех получателей не найдено.

## 1a. Accurate Analysis Module — Trigger 188/199, AGT 288/299, AGTAF 88/99/108/109

Соответствие фраз (`smac_ultra.phrases.txt`): `AimbotDetected_1` = Trigger, `_2` = Automatic Route Guidance (AGT; также
бан PRG), `_3` = After Firing (AGTAF), `_4` = AMSAF, `_5` = Null Level (AGTNL). Т.е. Trigger/AGT/AGTAF — это **не** детекты
в `OnPlayerRunCmd`, а оценка попаданий ниже.

Вызывается из обработчиков `player_hurt` (только `dmg_health ≥ 10`, жертва жива, не в себя) и `player_death`
(с `headshot`). Работает не по углам «в моменте», а по значению `dYawRef`, сохранённому в `OnPlayerRunCmd`
(отклонение текущего yaw от опорного угла), и по флагам streak-счётчиков PRG (`g3d840 > 0`).

* дистанция атакующий→жертва (квадрат): `< 200` — не анализируется; полосы `200..550`, `550..1300`, `>1300`;
* полосы `dYawRef`: `> 100`, `> 2`, `> 0.6`, `> 0.4` (те самые `BAND_*` из #7, но здесь это **разброс прицела на момент
  попадания**, а не дельта за тик);
* веса: обычное попадание +1, хэдшот или оружие из группы-2 (trie `4106`) +2; оружие из trie `4104/4105` — исключение/другая
  ветка; детект — когда взвешенный счётчик режима переходит порог (`_1` — g3d83c, `_2` — g3d844, `_3` — g3d85c/g3d8d0 вместе с
  hitgroup-счётчиками ≥ 4);
* в отдельной ветке (`Me45…`) для `player_hurt` сначала ставится отложенная проверка `SetBan(attacker, 12, …)`.

Уверенность: средняя (структура и пороги ясны, точная семантика «опорного угла» `g293bc` не восстановлена).

## 8. Cvars / команды (`001_SMAC_Cvars.smx`)

* Полная таблица проверяемых кваров (Check_Hack / Check_Changer / Check_CheatsC) — `docs/R52_CVARS.md`.
* **SIC «cheat class Iniuria CS:S»** (слушатель команд): поток команд без аргументов, счётчик > 23 в окне, и команда
  `spec_prev` → SIC-реакция (`smac_indirect_cheat`). Уверенность: средняя.
* Слушатель команд также блокирует `ent_create`/`ent_fire` по подстроке, ведёт спам-счётчик и «SayBlock».
* Квары `sv_cheats`, `host_timescale`, `sv_competitive_minspec`, `sv_consistency`, `mp_fadetoblack`, `sv_footsteps`,
  `sv_allowminmodels` — отслеживаются через `FindConVar` (replicated-проверка), а не жёстко форсятся.
